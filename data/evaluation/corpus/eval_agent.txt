Agent 用循环连接用户任务、模型判断和工具执行，使请求经多轮处理形成回答。Agent Loop 的过程是 Decision、Action、Observation，再进入下一次 Decision。Decision 是模型根据 messages 判断如何继续：可以直接给出最终回答，也可以提出 Tool Call。Action 是程序执行模型选定的工具，Observation 是程序把执行结果放回上下文，供模型下一轮判断使用。当前 KnowledgePilot 的 chat_with_ollama 接收 messages 和 max_steps，每轮向 Ollama 发送消息以及 calculator、search_knowledge_base 工具的 Schema。一个 Decision 轮可以产生多个 Tool Call，程序依次处理本轮的全部调用，工具调用次数与决策轮数需分别理解。

Tool Result 是一次工具执行产生的结果。calculator 通常返回计算数值，search_knowledge_base 返回包含内容与来源的片段列表。程序保存模型提出工具调用的 assistant 消息，再为每个结果追加 role 为 tool 的消息，其中 tool_name 标明工具，content 保存结果的字符串表示。下一轮模型便能够看到自己的调用和对应的 Observation，依据取得的信息继续处理任务。messages 承载一次运行的工作上下文，Tool Result 提供来自实际执行的依据。工具执行出现可捕获的异常时，程序会把错误整理为 Tool execution failed 开头的结果，作为 Observation 放回 messages，模型可以根据错误继续判断。工具返回空列表表示检索没有取得片段；执行失败则表示调用过程发生了问题。两种情况需区分。

max_steps 限制 Agent 的最大 Decision 轮数，默认值是五。进入一次循环并请求模型，就消耗一个决策轮；同轮即使执行多个工具，也只占一个轮数。工具执行后通常还需要下一轮模型整理结果并给出回答，因此工具调用与最终回答可能分属两个 Decision。模型本轮没有提出更多 Tool Call 时，函数返回 answer、trace 和 stop_reason，stop_reason 为 completed。completed 表示循环按停止条件结束，回答是否正确、是否充分仍需要依据问题和工具结果判断。若允许的轮数都用完，模型仍在请求工具，函数返回最大步骤限制提示，并将 stop_reason 设为 max_steps。这个上限为一次请求提供明确的停止边界，也让调用方能够区分正常停止与轮数耗尽。即使无需调用工具，一次直接回答也需要一次模型 Decision，仍占用一个轮数。

trace 记录 Agent 的工具执行事实。每个 Tool Call 对应一项，包含 step、tool、arguments、result：step 是从一开始的决策轮号，tool 是工具名称，arguments 是模型给出的原始参数，result 是执行结果或错误 Observation。同轮多个调用形成多项 trace，并共享相同 step。最终直接回答的轮次没有工具记录，因此直接回答可以具有空 trace，trace 长度代表工具尝试次数。answer、trace、stop_reason 共同构成 Agent Result。当前 /chat 为每个请求建立新的 system 与 user 消息，再调用 Agent；运行期间 messages 追加工具消息。这种上下文服务于当前请求，跨请求保留用户偏好或历史事实属于长期 Memory 的范围。当前 V1.1.0 的 stateless /chat 没有实现这类长期保存。
