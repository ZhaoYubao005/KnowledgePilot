## 真实模型失败与最小修复

没有将失败运行删除或计作成功：

- [首轮失败](v1.6-real-initial-failure.json)：同会话回忆和隔离已通过，在组合 restart 检查失败。
- [拆分诊断后的失败](v1.6-real-restart-failure.json)：重启前后 revision=2，完整历史一致，179字符，原事实仍保留；SQLite 持久化通过，但模型再次回忆返回未知。不是历史窗口溢出，也不是数据库丢失。
- 检查发现旧 direct 调用会在当前问题后追加一个空的 `Execution context` 用户消息。先补当前问题必须位于最后的失败测试，再**只修改有 Session 的 direct**提示：系统提示说明参考历史解析指代，历史后最后一条为当前 Query。无会话旧 payload 不改。
- 未扩大512字符验收预算、未放松语义断言，也未反复请求模型挑选成功样本。修复后执行一次完整真实验收，27请求/14检查通过；重启一致性与语义回忆分别验证。这是有限样例结果，不保证所有模型/所有指代均可靠。

其他按测试先行修复的问题：数据库 append 在不同预算下重复裁剪导致较旧可用轮次丢失；无效工具输出应标记 failed 而非保留 succeeded 诊断；配置错误不应吞为工具故障；空白完成答案转安全 ModelResponseError；会话 query 错误不再误报 invalid document。独立只读审查后未发现其他可操作问题。

开发中曾无参数 pytest 扫描到沙箱临时目录产生 WinError5，后改为显式 `pytest tests` 全量收集，不删除这些目录；另一次全量扫描恰遇新 HTTP 验收脚本尚未实现的预期测试先行失败。二者不计作通过，不属于最终619项运行。

## 已知限制和下一步

- 本地 bearer-capability 会话 ID 不是正式认证；无用户权限、TTL、全库 session 数量配额、加密或物理安全擦除。每会话历史有界，不代表 SQLite 总文件大小有界。仅受控本机使用，不直接公开部署。
- 历史按完整轮次字符计数，不是 token 控制；系统提示、当前 Query、RAG 证据不计入历史预算。超大历史轮次整体舍弃，较旧合适轮次可能保留，不保证记住所有事实。
- 恢复层作用于 Workflow 工具执行，不重写原 Agent Loop；旧 Agent 的失败 Observation/trace 仍可能包含原异常文本，这是保留路径的既存限制。新恢复诊断不含原始异常，日志继续使用原值脱敏格式器；不宣称整个旧 Agent 的响应脱敏问题已解决。
- 无自动摘要、长期用户画像、跨用户记忆、MCP 或多 Agent 产品能力。
- 保留 V1.4 Docker/独立 Linux 验证缺口、非原子文档更新和无认证技术债。未实施正式服务器部署。模型回忆改善有单次完整验收证据，不是语义准确率或负载稳定性保证。
