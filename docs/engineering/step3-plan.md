# V1.4 Step 3 implementation and design

Authorized scope: standard-library logging, error classification, safe HTTP mapping and transport reliability. Build on Step 2 commit eb53686253905e6b4e427a552d156708b7c49a0a, whose native deployment acceptance remains BLOCKED. Do not debug Docker, merge main, push, tag or change frozen evaluation inputs.

Chosen approach: keep existing route/service/Agent contracts and introduce small boundary modules (`errors.py`, `logging_config.py`, `llm/transport.py`, `api/reliability.py`). An alternative is adding catches to every function; it duplicates policies. An external logging/error framework would add dependencies without helping this scope. Standard logging and explicit boundary exceptions are sufficient.

2. Write failing tests for logging redaction, request IDs, safe traceback frames, handler idempotence and log levels; config validation; upstream connection/timeout/status/JSON/schema failures; and HTTP compatibility.
3. Implement structured stderr logging scoped to the knowledge_pilot logger. Log only fixed events and allowlisted metadata. Tracebacks retain module/function/line and exception types, excluding messages, source lines, locals and absolute paths. Do not configure the root logger or capture third-party logs as safe application events.
4. Add explicit ConfigurationError (ValueError compatible), InputError (ValueError compatible), ModelUnavailable, ModelTimeout, ModelResponseError and InternalServiceError. HTTP: 400 input, 422 request validation, 502 upstream response, 503 connection, 504 timeout, 500 internal/configuration. Startup configuration failure remains a startup failure, never a fake ready app.

Unexpected failures return generic 500 with a server-generated request ID and retain a sanitized traceback. Failures after response start cannot change HTTP status and must be logged distinctly.
