# KnowledgePilot V1.1 封版前工程记录

记录日期：2026-09-24。V1.1 的项目版本声明为 `1.1.0`；本记录不代表已经完成 Git commit、创建 `v1.1.0` tag 或 push。

## 已实现范围与验证

V1.1 在 V1.0 Agent Loop、Tool Calling、RAG 和 Chroma 核心之上增加 FastAPI 边界：`GET /health`、`POST /chat`、`POST /documents`、`GET /documents`、`PUT /documents/{document_id}`、`DELETE /documents/{document_id}`。API 使用 Pydantic 请求/响应模型、Service Layer、raw TXT 文件管理，以及 400、404、422、502、503 状态码映射和 OpenAPI 文档。API Contract 测试使用 Mock Service，不真实访问 Ollama、Embedding 或 Chroma。

封版前全量 unittest 回归：V1.0 原有测试 21/21、V1.1 API Contract 19/19，合计 40/40 通过；其中 Knowledge Base 集成测试在 `KNOWLEDGE_PILOT_RUN_INTEGRATION=1` 时真实调用本地 Ollama Embedding 和 Chroma 检索。由于当前受限执行环境对原始数据库只读，完整回归在原始 Chroma 的临时副本上完成；原始 Chroma 文件哈希在前后保持一致。

## 已知技术债与限制

1. **Update 非原子。** `src/knowledge_pilot/vector_store/chroma_store.py` 的 `update_document(file_path, document_id, collection)` 先调用 `delete_document()` 删除旧 Chunk，再调用 `ingest_document()` 写入新 Chunk。新 ingest 失败时，旧 Chroma Chunk 可能已丢失；没有自动 rollback。

2. **raw 文件只有最小补偿性回滚。** `src/knowledge_pilot/api/services.py` 的 `update_document_service()` 会在失败时恢复同名旧 raw 文件内容，或删除本次写入的不同名新 raw 文件。它不提供 Chroma transaction、snapshot 或 rollback，不能把旧 Chunk 自动找回。

3. **故障注入已复现上述风险。** 真实测试中暂停 Ollama 后，`PUT /documents/{document_id}` 因 Embedding 连接不可用返回 HTTP 503。此次不同名文件更新中，旧 raw 文件仍保留且内容未变，新 raw 文件未保留，但该 `document_id` 的旧 Chroma Chunk 数变为 0。此结果是已确认的 V1.1 技术债，不应宣称 Update 具备事务能力。

4. **Ollama HTTP 健壮性不足。** `embed_text()` 与 `chat_with_ollama()` 的 `requests.post()` 目前没有完整的 timeout、`raise_for_status()` 或响应 schema validation。现有 Route 可映射连接失败为 503、非 JSON 响应为 502，但不能据此认为所有 HTTP 非 2xx 或结构异常均已正确处理。

5. **TestClient 依赖兼容风险。** 当前测试会出现 `StarletteDeprecationWarning`：Starlette 的 TestClient 使用 `httpx` 的方式已被标记为弃用，提示未来改用 `httpx2`。当前 40 项测试通过；未来升级 FastAPI、Starlette 或 httpx 前需验证兼容性，本次不升级依赖。

6. **上传文件读取异常未专门映射。** `POST /documents` 和 `PUT /documents/{document_id}` 中的 `file.file.read()` 位于 Route 的 `try` 块外。极端文件读取异常不会进入现有 400/502/503 捕获分支，可能成为未处理的服务器错误。

7. **Chroma 路径依赖工作目录。** `chromadb.PersistentClient(path="data/vector_store")` 使用相对路径。应从项目根目录启动服务或测试，否则可能打开或创建另一个数据库。

8. **受限测试环境的只读数据库错误。** 在当前受限环境中直接运行全量测试，Chroma 初始化可能报 `attempt to write a readonly database`；这是环境权限限制，不是已证实的业务代码回归。使用临时 Chroma 副本并启用 Knowledge Base 集成测试后，40/40 通过；原始 Chroma 文件哈希未变化。不要通过修改原始数据库权限来掩盖该限制。

以上限制不包含 Memory、MCP、LangChain、Docker、Web UI 或事务性文档更新；这些均不属于 V1.1 已实现能力。
