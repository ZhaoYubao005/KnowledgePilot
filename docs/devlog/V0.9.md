### 问题现象

从 PyCharm 直接运行：

```python
search_knowledge_base(
    query="什么是机器学习",
    top_k=3,
)
```

返回：

```python
[]
```

### 根因

`chroma_store.py` 当前使用相对路径：

```python
path="data/vector_store"
```

原来的 PyCharm 临时运行配置把 Working Directory 设为：

```text
$PROJECT_DIR$/src/knowledge_pilot/tools
```

因此程序实际连接到了：

```text
D:\AI_develop\KnowledgePilot\src\knowledge_pilot\tools\data\vector_store
```

该位置的 `knowledge_pilot_docs` Collection 是空的。

**knowledge_base_tool 返回 [] 的根因是 PyCharm Working Directory 导致相对 Chroma 路径连接到了错误空数据库，而不是 search() 或 search_knowledge_base() 检索逻辑错误。**

### 修改内容

1. 新增稳定的 PyCharm Run Configuration：

   ```text
   .idea/runConfigurations/knowledge_base_tool.xml
   ```

2. 固定配置：

   ```text
   SCRIPT_NAME=$PROJECT_DIR$/src/knowledge_pilot/tools/knowledge_base_tool.py
   WORKING_DIRECTORY=$PROJECT_DIR$
   PYTHONPATH=$PROJECT_DIR$/src
   Python=D:/Anaconda/envs/knowledge-pilot/python.exe
   ```

3. 从 `.idea/workspace.xml` 移除同名的错误临时配置，继续保留 `Python.knowledge_base_tool` 为当前选中的运行配置。

4. 未修改 `knowledge_base_tool.py`、`chroma_store.py`、Embedding、RAG Pipeline、calculator、Registry、Schema 或其他业务逻辑。

5. 未删除以下误生成目录：

   ```text
   src/knowledge_pilot/tools/data/
   src/knowledge_pilot/vector_store/data/
   ```

## 2026-09-11：修正 knowledge_base_tool 的 Tool Result Formatting

| 日期 | 修改位置 | 修改内容 | 验证结果 | 范围限制 |
| --- | --- | --- | --- | --- |
| 2026-09-11 | `src/knowledge_pilot/tools/knowledge_base_tool.py` | 将错误的 `score` Metadata 映射替换为 `source` 映射 | `knowledge_base_tool.py` 与 `registry.py` 均返回 3 条严格的 `content + source` 结果，所有 `source` 均非 `None` | 未修改 search、Chroma、Embedding、Schema、Registry 或其他业务逻辑 |

### 修改前验证

在修改前分别通过 `search_knowledge_base()` 和 Registry 的 `execute_tool_call()` 执行查询：

```text

top_k=3
```

两条路径都返回 3 条结果，但字段为：

```text
[content, score] × 3
content + source 契约=False
```

该失败验证确认了问题来自 Tool Result Formatting，而不是 Registry 调度、Chroma 连接或检索数量。

### 实际修改

只修改了一行：

```python
# 修改前
"score": metadata.get("score")

# 修改后
"source": metadata.get("source")
```

`search()` 返回的真实 `score` 仍由三元组的第二个元素提供；本次按照当前 Tool Result 契约不对外返回 score，只从 Metadata 中读取真实存在的 `source`。
